# 文本保护规则（text_preserve）

放这里的规则告诉工具：**哪些写法必须原样保留**，不许被翻译、改写、丢掉。

## 什么时候需要加规则

翻译跑完以后，日志和「未识别控制码报告」会列出原文里**工具认不出来**的  
`\xxx` 写法。那些就是你的游戏特有的控制码 —— 加一条规则把它们保护起来。

例：`\xn[Leticia]` 这种带参数的说话人标签，内置规则认不出来时  
整个前缀都不会被剥离，标签会跟着正文一起送去翻译。  
内置规则已覆盖它，游戏里若有别的写法就在这里补。

## 三档模式

在「设置」或「游戏汉化」页切换 `文本保护规则模式`：

| 模式          | 含义                                                  |
| ----------- | --------------------------------------------------- |
| `off`       | 只用工具内置的识别规则（`\命令[参数]`、单字母、`\$` `\.` `\|` 等符号码、`%1`） |
| `smart`（默认） | 内置规则 + 本目录的 `base.json`、`rpgmaker.json`             |
| `custom`    | `smart` 的全部 + 你自己的 `custom.json`                    |

改完规则文件后在界面上点「重载规则」即可生效，不用重启。

## 文件格式

JSON 数组，每项一个对象：

```json
[
  {
    "src": "正则表达式",
    "info": "这个规则保护什么（只给人看，不参与匹配）"
  }
]
```

正则匹配到的**整段**会被当作控制码：原样送模型、翻完检查还在不在，  
丢了就按原文补回。

## 注意事项

- `src` 是正则，反斜杠要写两个：保护 `\m` 要写 `"\\\\m"`。
- **别写“能匹配空串”的规则**（如 `.*?`、`^`、`a{0,1}`），会到处乱命中。
- 别写太宽的规则（如 `\{.*\}`），会把正文一起保护起来、结果正文不翻了。  
  拿不准就写窄一点，再加第二条。
- 长写法要排在短写法前面，否则会被短的截胡：  
  保护 `\opog` 和 `\op` 时写 `"\\\\opog|\\\\op"`。

## 例子

```json
[
  { "src": "\\\\xn\\[[^\\]]{1,40}\\]", "info": "说话人标签：\\xn[Leticia]" },
  { "src": "\\\\[A-Z]{2,4}",           "info": "本作自定义的全大写两位以上命令" }
]
```
